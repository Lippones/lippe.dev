Como o realtime funciona

um poll, muitos visitantes

O Spotify não tem webhook de playback: não existe ninguém para avisar o site que a faixa mudou. Então "tempo real" aqui é uma coisa só — um poll compartilhado no servidor, e a barra andando sozinha no navegador. O visitante vê movimento contínuo sem que exista uma requisição por quadro.

Setup · uma vez, fora do site

Você autoriza a sua própria conta

Não há login de visitante. Você roda o fluxo de autorização uma vez, com o escopo mínimo, e guarda o refresh token como segredo do projeto.

scope: user-read-currently-playing
env: SPOTIFY_CLIENT_ID · SPOTIFY_CLIENT_SECRET · SPOTIFY_REFRESH_TOKEN

o token nunca sai do servidor
Servidor · Route Handler

/api/now-playing

  1. 01Pega o access token do cache em memória, ou renova com o refresh token quando faltam menos de 5 min para expirar.
  2. 02Chama GET /v1/me/player/currently-playing uma única vez.
  3. 03Reduz a resposta a oito campos. O bundle do cliente nunca vê token, device id nem o resto do payload.
  4. 04Devolve com cache compartilhado, então a resposta serve todos os visitantes ao mesmo tempo.

Cache-Control: s-maxage=5, stale-while-revalidate=25

Cliente · a parte que parece mágica

A barra anda sem rede

  1. 01Ao receber o payload, o cliente guarda recebidoEm = Date.now(). Usar o próprio relógio evita erro de fuso e de máquina desregulada.
  2. 02A cada quadro, o progresso é progressMs + (agora − recebidoEm). Nenhuma requisição envolvida.
  3. 03Refaz o fetch a cada 10 s, ao voltar o foco da aba, e no instante em que o progresso local passa da duração — que é quando a faixa provavelmente virou.
  4. 04Aba escondida para tudo: sem timer, sem fetch, sem animação.

Se um dia precisar ser instantâneo

Trocar o poll do cliente por SSE: o servidor continua consultando o Spotify a cada 5 s e empurra só quando a faixa muda. Ganha-se a troca instantânea e paga-se com uma conexão aberta por visitante. Não vale a pena antes de alguém reclamar dos 10 s.
