O tetoThe ceiling

A primeira versão nasceu em FlutterFlow para validar rápido — e funcionou. Só que cada ajuste de UX, cada integração nova e cada bug em produção passou a custar caro demais. The first version was built in FlutterFlow to validate fast — and it worked. But every UX tweak, every new integration and every production bug started costing far too much.

A migraçãoThe migration

Levei o app para React Native com Expo e TypeScript: navegação redesenhada, design system interno, consumo de API organizado e releases OTA no fluxo — correção no mesmo dia, sem esperar a loja. I moved the app to React Native with Expo and TypeScript: reworked navigation, an internal design system, clean API consumption and OTA releases in the flow — same-day fixes, no store review wait.

DepoisAfter

Uma base que o time lê e evolui. Features saem em dias, não semanas, e o app deixou de ser protótipo para virar produto — com um dev responsável de ponta a ponta. A codebase the team can read and grow. Features ship in days instead of weeks, and the app stopped being a prototype: it's a product now, owned end to end.

SobreAbout

Não acredito em app bonito que trava. Interface é o que a pessoa vê; o resto é o que faz ela voltar amanhã. I don't believe in a beautiful app that stutters. Interface is what people see; the rest is what makes them come back tomorrow.

Comecei em frontend, atravessei backend e parei no mobile porque é onde as duas coisas se encontram sem lugar para esconder erro. Trabalho melhor quando sou dono de algo do começo ao fim: decido a arquitetura, entrego a tela, subo o release e olho o que aconteceu depois. I started in frontend, went through backend and stopped at mobile because that's where both meet with nowhere to hide a mistake. I work best when I own something end to end: I decide the architecture, ship the screen, cut the release and watch what happens next.
